Set up a real-time change data capture pipeline that streams changes from a PostgreSQL database into Snowflake. Use Kafka Connect with the Debezium PostgreSQL connector to capture WAL changes. The Kafka topics should be partitioned by table name with a retention of 7 days. On the Snowflake side, use the Snowflake Kafka Connector to land data into raw staging tables. Then create dynamic tables with an incremental refresh lag of 1 minute for the silver layer that handles deduplication, schema evolution, and late-arriving data. The gold layer should be another set of dynamic tables with 5-minute lag that performs aggregations and joins across the CDC streams. We need proper error handling — a dead letter queue for malformed records, alerts when the connector falls behind, and a reconciliation process that compares source row counts to target counts daily. Also configure network policies to restrict the Kafka connector IPs using network rules and set up PrivateLink between the Kafka cluster VPC and Snowflake.
