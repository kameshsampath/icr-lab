Set up programmatic access for a CI/CD service account in Snowflake. First, create a dedicated service user called SVC_DEPLOY_BOT with TYPE=SERVICE and DEFAULT_ROLE=DEPLOYER. Then create the DEPLOYER role and grant it USAGE on warehouse DEPLOY_WH and USAGE on database PROD_DB. Grant the DEPLOYER role to the service user. Next, create a network rule called CICD_EGRESS_RULE with TYPE=HOST_PORT, MODE=EGRESS, and VALUE_LIST containing our GitHub Actions runner IPs (52.186.44.0/24, 20.201.28.0/24) so the service account can only be used from known CI infrastructure. Create an external access integration called CICD_EXTERNAL_ACCESS that references the network rule and is enabled. Now create an authentication policy called CICD_AUTH_POLICY that allows only PROGRAMMATIC_ACCESS_TOKEN as the client type and sets TOKEN_VALIDITY_TIME_IN_SECONDS to 3600 (1 hour expiry for short-lived deploys). Apply the authentication policy to the SVC_DEPLOY_BOT user with ALTER USER SET AUTHENTICATION POLICY. Generate a programmatic access token for the service user using SYSTEM$GENERATE_PROGRAMMATIC_ACCESS_TOKEN with lifetime=3600. Finally, verify the setup by connecting as SVC_DEPLOY_BOT using the PAT and running SELECT CURRENT_USER(), CURRENT_ROLE(), CURRENT_WAREHOUSE() to confirm identity, role, and warehouse are correct. Also run SHOW PARAMETERS LIKE 'NETWORK_POLICY' IN USER SVC_DEPLOY_BOT to verify the network restrictions are in effect.
